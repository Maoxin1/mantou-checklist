# mantou 定投清单

一个本地优先、可离线使用的个人长期行动清单生成器。日常只需要更新少量事实，就能自动汇总状态并生成一张 1080 × 1536 PNG，适合发布到微信群、社群或个人博客。

> 这里的“定投”不只指金钱，也指把时间持续投入认知、表达、身体与长期能力。

## 在线使用

- 桌面版：<https://mantou-checklist.pages.dev/>
- 手机编辑器：<https://mantou-checklist.pages.dev/editor>

## 个性化（Issue #25）

桌面版和手机编辑器的「高级设置」支持修改 PNG 标题、三项记录名称，以及每行一个的额外训练选项（最多 8 项）。例如将三个记录名称设为「阅读1h+ / 运动 / 表达」，并为运动添加「游泳、乒乓球」。

- 三项记录的**类型保持不变**：分钟、活动选项、完成/未完成。改名不会重置历史，也不会把分钟记录变成复选框。
- 只有明确选择「力量训练」才计入原来的每周力量训练次数。其他活动原样保存并显示，不误算为力量训练。
- 默认训练选项不删除，移除自定义候选项也不会抹除之前记录的活动；原有日报、备份与离线结构保持兼容。
- 个人标题仅用于生成的 PNG 和文件名；PWA 安装名称仍是「mantou 定投清单」。图片底部保留来源品牌。
- 不新增每日打卡字段，也不新增账户、同步或通用习惯编辑器。

## 日常使用

V2 将日常输入收敛为 3 个字段：

1. 阅读与思考分钟（阅读、理解及相关思考的合计时间）
2. 今日训练：力量训练 / 羽毛球 / 激活 / 恢复 / 未训练
3. 日记完成状态

日期可在主界面切换。主实验、当前阅读和本周交付物都属于低频设置，正常一天不需要修改。

系统会自动计算：

- 本周阅读与思考时间
- 本周力量训练次数
- 当前周状态
- 1080 × 1536 公开 PNG

时间只记录投入，不代表理解或能力的达标。当前实验为“作息重构 · 进行中”；十本书的完整队列与周复盘留在已有阅读笔记中，本应用不增加每日打卡项或历史系统。

升级时会把已知的旧阶段、泛化书名及“完成14天 V1 验收”默认文案更新为当前安排，保留自定义内容、阅读记录、训练与累计日记。投资栏已从表单和图片移除；旧备份中的投资文字仅为兼容而保留，不再展示。

目标是从打开 PWA 到生成图片，正常情况下不超过 15 秒。

PNG只展示当天实际训练状态和本周次数。羽毛球可以保存、备份恢复和展示，不计入力量训练次数。实际活动由本人手动记录。

## 它能做什么

- 记录每日 3 个最小事实并自动保存
- 自动汇总当前周阅读时长和力量训练次数
- 记录当前作息实验、两本书的阅读方式与可选的本周交付物
- 实时生成与 mantou 博客一致的暖纸色“行动档案”图片
- 一键下载 1080 × 1536 PNG
- 首次联网安装后离线填写、预览和下载
- 导出 JSON 备份，并在另一台设备手动导入恢复
- 兼容旧版本地数据，自动迁移上一阶段默认字段
- 针对触控、窄屏和主流移动端浏览器设计

## 隐私与数据边界

这个项目没有后端数据库，也没有接入统计脚本。表单数据和自动保存内容默认只写入当前浏览器的 `localStorage`。

V3 按日期保留每日行动分钟、训练状态和日记完成状态，支持跨周补录。主界面可选过去日期、前后切换并回到今天，禁止填写未来日期。周统计按所选日期所属周汇总；累计日记由历史起始值加全部已完成记录计算。重复保存不会重复计数。未填写日期显示待记录；若当日全部未完成，可点击“确认当日记录（含未完成）”。阶段设置仍为全局当前值，不提供历史阶段快照。

新的一天会自动切到今天；若正在补记过去日期，则继续停留在所选日期。换周保留全部每日记录。旧数据迁移保留现有累计数与尚存周日志；旧版已删除的明细无法自动恢复，补录前请确认该日未包含在原累计数中，必要时校正累计总数。它不是健康数据库，也不会记录或公开具体血糖、症状、睡眠原始日志、仓位、金额等私人数据。

保存失败时会明确提示，当前填写仍留在页面内，PNG 和 JSON 备份下载不依赖本机存储可用。关闭或刷新前请先从本页的“本地数据管理”导出备份。

多个窗口同时使用时，无待保存修改的窗口会同步新数据；存在未保存修改或错过同步的旧窗口会停止覆盖，提示先导出该页备份再刷新。支持 Web Locks 的浏览器会串行检查和写入；较老浏览器使用最新值检查，极端同时写入仍建议只开一个编辑窗口。

导入会检查备份版本、字段类型、真实日历日期与周日志一致性。仍兼容旧版原始状态和 v1/v2/v3 备份，保留现有 localStorage 键。旧版界面允许手动把累计日记设得低于本周已完成天数；加载此类旧本地数据时，会保留清单并将累计数校正到已完成天数，同时明确提示原值和校正值。只在之后保存时写回；导入文件仍需满足完整校验。导入前先保存一份本机恢复副本；若无法保存副本或新状态，则不改变原清单。最近一次导入前的副本可用“下载导入前备份”取回，下一次成功写入恢复副本时会替换它。清理浏览器数据也会移除该副本。导入会恢复备份中全部日期的明细，替换而非合并当前记录。

建议定期打开“本地数据管理”，下载 JSON 备份。不要在公开 Issue、聊天群或截图中上传包含私人信息的备份文件。

## 移动端安装与离线使用

应用名称统一为 **mantou 定投清单**。手机使用与安装推荐从 `/editor` 进入；手机页右上角“桌面版”返回根页面，两个入口保留各自已有的安装身份。升级保留本地数据键，新导出使用 v3 格式并兼容导入旧备份。旧版应用不支持 v3 备份。

### Android

1. 使用 Chrome、三星浏览器或其他支持 PWA 的浏览器打开[手机编辑器](https://mantou-checklist.pages.dev/editor)。
2. 点击页面右上角的“安装”。
3. 如果没有弹出安装窗口，请打开浏览器菜单，选择“安装应用”或“添加到主屏幕”。

### iPhone / iPad

1. 使用 Safari 打开[手机编辑器](https://mantou-checklist.pages.dev/editor)。
2. 点击“分享”，选择“添加到主屏幕”。
3. 开启“作为 Web App 打开”，然后点击“添加”。

第一次加载和安装需要网络。成功打开一次后，即使暂时断网，仍可填写、预览、备份并下载图片。

## 本地运行

需要 Node.js 22+，推荐与 CI 一致的 Node.js 24。

```powershell
git clone https://github.com/Maoxin1/mantou-checklist.git
cd mantou-checklist
npm ci
npm run serve
```

打开：

- <http://127.0.0.1:4173/>
- <http://127.0.0.1:4173/editor>

常用命令：

```powershell
npm run check
npm test
npm run test:browser
npm run smoke:local
npm run build
```

## 默认配置

常用默认文案集中在 `config.json`：

- `diaryDay`：累计有效日记天数起点
- `bodyPhase` / `bodyMeta`：当前主实验与阶段补充
- `readingPhase`：当前阅读材料与方式，每行一本（默认精读《Beyond Feelings》、略读《The Craft of Research》）
- `readingTargetMinutes`：每日阅读与思考计划（90 分钟）
- `weeklyReadingTargetMinutes`：每周阅读与思考保底（450 分钟 / 7.5 小时），其余时间弹性安排
- `weeklyStrengthTarget`：每周力量训练参考次数（当前3次）
- `trainingTrial`：上一期两周试行的固定起止日期，保留历史说明
- `trainingPlan`：当前持续阶段的固定开始日期、名称与 A/B/C 安排，没有滚动结束日期
- `nextResult*`：最多三个可选的本周交付物及验收状态；默认留空，全空时图片不绘制此板块
- `motto`：长期口号

视觉颜色和手机布局位于 `styles.css`、`editor.css`；1080 × 1536 成图规则位于 `app.js`。

## Cloudflare Pages 部署

本项目保持 **Direct Upload + 本机手工发布**。GitHub Actions 只负责代码验证，不保存 Cloudflare 部署凭据。

首次在一台电脑部署，或 Wrangler 登录状态失效时：

```powershell
npx wrangler login --device
```

之后每次正式发布只需要：

```powershell
git pull
npm ci
npm run deploy
```

`npm run deploy` 会依次执行 JavaScript 检查、生产构建，并把 `dist/` 上传到现有的 `mantou-checklist` Cloudflare Pages 项目。

发布后如需额外核查正式站，可手动运行现有的 Production smoke workflow；日常不需要配置 `CLOUDFLARE_API_TOKEN` 或 `CLOUDFLARE_ACCOUNT_ID` 到 GitHub。

